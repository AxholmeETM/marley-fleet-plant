# Database

## Engine

- **Production:** Postgres on Supabase, reached through Cloudflare Hyperdrive `marley-db` (caching off).
- **Local:** embedded PGlite in `DATA_DIR/pgdata` when `DATABASE_URL` is unset.
- The schema lives in `SCHEMA` in `src/db.js`. It runs on every start and is written to be safe to repeat (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`). Row level security is switched on for every table in `TABLES`, so Supabase's public API can't read anything; only the app (service connection) can.

## Conventions

- Table names are plural snake_case (`fuel_cards`); columns snake_case.
- Primary key `id INTEGER GENERATED BY DEFAULT AS IDENTITY` (except `projects.code` and `settings.key`).
- **Dates are TEXT** in ISO form: `YYYY-MM-DD` for dates, `YYYY-MM-DD HH24:MI:SS` (UTC) for timestamps (`created_at`).
- Booleans are `INTEGER` 0/1 (`active`, `verified`, `planned`).
- Enumerations are TEXT with a `CHECK` where the set is fixed; their labels live in `src/categories.js`.
- SQL in the app uses `?` placeholders; `db.js` turns them into `$1, $2…`.

## Rules

- **Never delete history.** Leavers are made inactive (`users.active = 0`); sold, stolen or scrapped assets get a status. Hard deletes are limited to things entered by mistake (a fuel card, an uploaded mileage week, a document).
- **One source of truth for who has what.** `vehicles.driver_id` is the driver. A person's fuel cards follow their vehicle (`syncCardVehicles` in `src/queries.js`). Only past fuel entries keep the reg they were logged against.
- Site manager access is decided by `plant.job_ref` matching a project whose `manager_id` is them.
- Run-once data jobs record a `settings` key so they never run twice (`employees_from_fuel_cards`, `cards_follow_vehicles`, `cards_match_drivers`).

## Migration rules

- Add to the end of `SCHEMA`, using `IF NOT EXISTS` / `IF EXISTS` so it is safe on every start and on both Postgres and PGlite.
- To change a `CHECK`, drop and re-add the constraint (see `service_records_kind_check`).
- Add any new table to `TABLES` so it gets row level security.
- Never drop a column holding real data without Ben's say-so; stop using it first.
- One-off data fixes for the live database go in a `.sql` file in the project files `data-import/` folder, which Ben runs in the Supabase SQL Editor.
